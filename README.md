# 尘叙阁 · 图文分享社区（前端）

图文分享社区的前端实现，围绕「记录日常」这个场景，提供图文动态发布、话题聚合、照片墙时间轴、评论树与好友关系。

配套后端：[share-system](https://github.com/76we/share-system) — Spring Boot 3 + MySQL + Redis。

> 线上地址：部署完成后更新于此

## 功能

| 模块 | 内容 |
| --- | --- |
| 账号 | 注册（邮箱验证码）、登录、JWT 鉴权、全局路由守卫 |
| 信息流 | 分类筛选、关键词搜索、只看朋友、时间/热度排序、分页加载 |
| 发布 | 最多 9 图上传、地点与心情标签、编辑、删除 |
| 详情 | 图片预览、二级评论树、点赞、收藏 |
| 个人中心 | 我的动态 / 点赞 / 收藏三个标签、资料编辑 |
| 照片墙 | 按月分组时间轴、相册管理、好友墙聚合 |
| 话题 | 话题详情、卷内序号排版 |
| 其它 | 站内通知、好友申请与同意、分享卡片 |

## 技术栈

Vue 3.4（Composition API + `<script setup>`） · Vite 5 · Vue Router 4 · Element Plus 2.8（按需引入） · Axios

## 值得说明的几处实现

### 图片上传：压缩放在前端做

手机直出的照片普遍 4000px / 3–5MB，九张一次上传会把弱网下的等待拖到几十秒，后端也要为大图解码分配大块堆内存。所以在上传前先压一遍：

- `createImageBitmap(file, { imageOrientation: 'from-image' })` 让浏览器按 EXIF 方向解码，竖拍照片不会躺倒；环境不支持时回退 `<img>` + canvas
- 长边压到 1600、JPEG q0.82，**串行**处理 —— 并发解码 9 张 4000×3000 大约占用 400MB 内存，移动端会直接崩
- 透明 PNG 转 JPEG 前先铺白底，否则透明区域会变成黑色
- 尺寸和体积都没超阈值时原样上传，避免无谓的二次编码掉画质

实测 4032×3024 / 1.4MB 的原图 → 1600×1200 / 162KB，耗时 179ms；9 张合计 12.9MB → 1.4MB。

后端还会做一次兜底压缩并生成缩略图，同时用文件头和像素总数做校验（挡住改后缀的伪装文件与解压炸弹）。

### 首屏体积

| | 优化前 | 优化后 |
| --- | --- | --- |
| 首屏 JS + CSS（raw） | 716 KB | 370 KB |
| 同上（gzip） | 214 KB | 128 KB |
| 构建产物总量 | 13.7 MB | 1.3 MB |

三件事：

1. **路由懒加载** —— 7 个视图改成 `() => import()`，打开登录页不再下载照片墙、相册管理这些用不到的代码。配套加了 `router.onError` 兜底：发版后旧页面里的动态 import 会 404，捕获后整页刷新一次拿到新入口（10 秒防抖，避免 CDN 还在发旧 HTML 时无限刷新）
2. **Element Plus 按需引入** —— 全站只用到 9 个组件，整包引入要多背 947KB JS + 458KB CSS。注意 `manualChunks` 里不能再写 `'element-plus': ['element-plus']`，那等于把整包强行拉回来，按需引入会被完全抵消
3. **清理未引用的素材** —— 8.7MB 与 2.6MB 的两个背景视频、一张旧静帧、以及一个从未被 import 的主题样式文件

### 卡片组件化

首页信息流、个人中心、话题页原本各有一套动态卡片模板与样式，三份代码已经开始漂移（同一个时间格式化有 5 份拷贝，口径还不完全一致）。合并成 `MomentCard.vue` 后用 `variant` 区分两套皮肤：

- `variant="feed"` —— 首页（左文右图的头条、短句松排版）
- `variant="ink"` —— 个人中心与话题页（卷内序号、标签式 meta）

两套皮肤的视觉规则全部带 variant 前缀，只共享没有视觉属性的行为规则 —— 否则一套皮肤的标题行高会漏进另一套，把话题页标题撑大一号。

顺带补上 `role="link"` + `tabindex="0"` + 回车跳转 + `:focus-visible` 描边：卡片原本只能用鼠标点开，键盘完全进不去。

### 请求竞态

快速切换筛选条件或标签页时，先发出的请求可能后返回，把新数据覆盖掉。处理方式：

- 列表请求带递增序号，响应回来时序号已变则整包丢弃（连 loading 状态都不还原）
- 分页「载入更多」**不自增**序号 —— 它属于当前这版列表，中途换了筛选条件就该作废
- 另加一个 in-flight 标记，避免连点造成重复追加

### 一个字体缺字问题

全站每个「回」字都显示成实心方块，其它汉字正常。原因是 Google Fonts 的分片版 ZCOOL XiaoWei 在 `unicode-range` 里声明覆盖了 U+56DE，但对应分片文件里并没有这个字形 —— 浏览器认为「这个字体负责这个字」，不会回退到后备字体，直接画 `.notdef` 方框。

修法是单独声明一个只负责这个码位的本地字体，排在网络字体前面：

```css
@font-face {
  font-family: 'ZW-Gap';
  src: local('PingFang SC'), local('Microsoft YaHei'), local('Heiti SC');
  unicode-range: U+56DE;
}
```

### 移动端

- `100svh` 代替 `100vh` —— 移动端地址栏收起/展开时 `100vh` 会让页面高度跳动
- 输入框强制 16px —— iOS Safari 在 `font-size < 16px` 时聚焦会自动放大整个页面
- 五档宽度（360 / 375 / 390 / 414 / 768）逐页验证过横向溢出与元素越界

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5173
```

开发环境通过 Vite proxy 把 `/api` 与 `/images` 转发到 `http://localhost:8080`，后端地址在 `vite.config.js` 顶部的 `BACKEND` 常量里改。

```bash
npm run build    # 产物在 dist/
npm run preview  # 本地预览生产包
```

## 目录结构

```
src/
├── views/        7 个页面，全部路由懒加载
├── components/   卡片、评论、发布弹层、相册管理等 10 个组件
├── utils/        请求封装、图片压缩、格式化、URL 处理
├── router/       路由、守卫、懒加载失败兜底
├── style.css     主题变量与全局样式
├── App.vue       导航、通知面板、全局布局
└── main.js       axios 配置与拦截器
```

## 部署

前端为纯静态产物，构建后由 Nginx 托管，`/api` 反向代理到后端，上传的图片由 Nginx 直读磁盘（不经过应用）。完整部署步骤见后端仓库的 `deploy/DEPLOY.md`。
